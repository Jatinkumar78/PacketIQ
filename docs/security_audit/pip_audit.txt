Status of that finding, checked against PyPI and OSV on 2026-08-10:

  - diskcache 5.6.3 is simultaneously the newest release in existence
    and the affected one; the advisory range is "introduced: 0,
    last_affected: 5.6.3" with no fixed version.  There is nothing to
    upgrade to.
  - pySigma 1.5.0 (latest) still declares diskcache>=5.6.3,<6.0.0, so
    the pin cannot be relaxed from our side either.
  - Aliases: CVE-2025-69872, GHSA-w8v5-vhqr-4h9v.  Unsafe pickle
    deserialisation; CVSS 4.0 AV:L/AC:L/PR:L/UI:A — it requires an
    attacker who already has write access to the cache directory.
  - PacketIQ imports neither diskcache nor pySigma anywhere in
    packetiq/ (grep: no matches).  pySigma is used only by
    tests/test_sigma_pysigma.py, to confirm the rules PacketIQ writes
    parse under a real Sigma implementation.

Conclusion unchanged: not exploitable through PacketIQ, and not present
in any user's install.  Reported on every run rather than suppressed.

Why a fresh venv, not the developer venv
---------------------------------------------------------------------
Running pip-audit inside the long-lived developer venv on this date
reported 7 vulnerabilities across 4 packages (aiohttp, cryptography,
diskcache, pypdf).  That is a property of *that venv*, not of PacketIQ:
its packages had drifted behind the current releases, and three of the
four are not in either closure this project ships or declares.

  - cryptography 49.0.0 (PYSEC-2026-3552) — the only declared runtime
    dependency among them.  The floor "cryptography>=44.0.1" resolves to
    50.0.0 on a clean install, which is the fixed version, so a user's
    install is unaffected.  The developer venv simply had not been
    upgraded.
  - aiohttp 3.14.1 and pypdf 6.14.2 — absent from both the runtime and
    the dev closure (verified: neither appears in a clean "pip install
    .[dev]").  They are incidental tooling installed into that venv.

Takeaway for anyone re-running this: audit a freshly built closure.  An
audit of a developer venv measures the developer's machine, and will
over-report against what users actually install.
